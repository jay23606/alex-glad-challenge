## Что сломалось / находки smoke

1. **Двойная cookie-доменная ловушка при локальном smoke:** половина навигации
   приложения живёт на `127.0.0.1`, половина переходов нормализуется к
   `localhost` — cookie в этих хостах НЕ разделяются, сессия «пропадает» между
   переходами. Для smoke зафиксировано правило: один хост на весь сценарий.
   Кандидат на канонизацию хоста в `next.config.ts` (отдельная задача, не в Дне 3).
2. Ссылки футера на узком вьюпорте (1365×768) частично перекрыты фиксированной
   нижней навигацией (клик по «todos» блокируется `<svg>` нижней панели) —
   кликабельность восстанавливается скроллом; на функциональность не влияет.
3. Маршрут задач `/mcp/todos` неочевиден: короткий URL `/todos` даёт 404.

## Flow после PR (issue #17)

Чек-лист единого отчёта после PR (выполняется агентом):

1. `pnpm --filter challenge typecheck` → `pnpm --filter challenge test`.
2. `pnpm --filter web typecheck` → `pnpm --filter web test` (`--maxWorkers=2` на этом хосте).
3. Поднять `pnpm --filter web dev` (loopback) → прогнать smoke-сценарии S1–S6 через MCP → скриншоты.
4. Свести отчёт: таблица сценарий/ожидание/факт/скриншот + падения с местом поломки.

Сценарий «я задеплоил новую фичу — обнови smoke»: (а) прочитать CHANGELOG/дифф
фичи → (б) сформулировать 1 новый пользовательский сценарий по фиче → (в)
добавить его в этот файл с разделом и прогнать → (г) отметить в отчёте. Репетиция
выполнена на фиче Blogs Foundation (S6 выше).
