Все показы — реальные файлы репозитория, не слайды. День про профили агентного
режима: как превратить «опыт предыдущих сессий» в формальные процессы.

## 0:00–0:40 — Задача

Говорить:

- Задание дня: формализовать два профила агентного режима — «Поиск бага» и
  «Research» — с системным промптом, списками ДОЛЖЕН / НЕ ДОЛЖЕН и форматом
  ответа, и проверить каждый на реальной задаче с первого запуска.
- Усиление: третий профиль под частую задачу — выбран «Граф проекта».

Говорить:

  opus/sonnet/haiku-классами и `subagent_type`, которых в текущем стеке нет.

## 1:40–3:00 — Четыре профиля

Показать в `AGENTS.md`:

- §13.1 — таблицу триггеров (ключевые слова запроса → профиль);
- §13.2 — общие STRICT-правила стадий (два канала контекста, нейминг
  `swarm-report/`, лимиты fan-out, барьеры);
- §13.3–13.6 — сами профили.

Говорить:

- «Бизнес-фича» и «Поиск бага» — перенесены со стадийными графами:
  `Research → Plan → Fix → Validation → Report` и
  `Diagnose → Reproduce → Fix → Validation → Report`, с запрещёнными переходами
  и лимитами откатов.
- «Research» — read-only: каждое утверждение с `file:line`, честный блок
  «не проверено».
- «Граф проекта» — уровни: поверхности → web-server → core → данные.
