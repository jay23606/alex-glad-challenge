# Orchestrator — как запускать

Файловый multi-agent флоу: main-agent ведёт процесс и состояние, код пишут
субагенты. Схема: `flow.excalidraw` / `flow.png`. Канон состояния:
`state.json`.

## Запуск

Один из вариантов:

- `/skill:orchestrator-run` в omp-сессии;
- обычным текстом: «Проведи ресерч, сделай эпик и реализуй по сториям: <цель>».

В запросе дайте: цель, ограничения, критерии приёмки и что **не** входит.

## Файлы

| Файл | Смысл |
|---|---|
| `state.json` | фаза + статусы сторий, точка возобновления |
| `research.md` | выводы ресерча (создаёт `product-researcher`) |
| `epic.md` | цель/границы эпика (создаёт `story-planner`) |
| `stories/NN-slug.md` | карточки сторий в порядке реализации |

`state.json` руками не правим: его обновляет оркестратор. Прервались/почистили
контекст — `/new`, затем «продолжай по `docs/orchestrator/state.json`».

## Роли

- `product-researcher` — read-only, пишет только `research.md`.
- `story-planner` — read-only, пишет `epic.md` + карточки сторий.
- `project-implementer` — реализует одну сторию; вход — одна карточка.
- `project-reviewer` — read-only ревью diff.
- Валидация (`typecheck`, тесты, smoke) — один раз после интеграции стории.

## Gate-точки для человека

1. После `research.md` — согласовать выводы и открытые вопросы.
2. После `epic.md`/сторий — согласовать нарезку и порядок.
3. Перед merge — посмотреть diff и результат валидации.

## Правила

- Одна итерация = одна стория; не влезла — вернуть planner'у на нарезку мельче.
- Main-agent не пишет и не читает код в основном контексте, кроме разбора
  blocker.
- Commit/push/зависимости — только по явной команде пользователя.
