# Видео-сценарий — ADVANCED Day 4: Local Boost

Цель видео: показать, как локальная LLM работает как код-ассистент внутри
проекта `alex-glad-challenge`, и честно сравнить её с облачным ассистентом
на тех же задачах из Дней 1–2.

Целевая длительность: 8–10 минут.

---

## 0:00–0:45 — Вступление и постановка задачи

**На экране:** терминал + VS Code с открытым репозиторием.

**Что говорить:**

- День 4 — про локальную LLM как код-ассистента в IDE.
- Главный вопрос: может ли локальная модель заменить облачного ассистента
  на реальном проекте?
- Железо намеренно обычное: x64, 12 ядер, 16 GB RAM, без GPU — то, что есть
  у большинства разработчиков.
- Связка: Ollama (`127.0.0.1:11434`) + Continue.dev в VS Code.
- Модели подобраны под RAM: `qwen2.5-coder:7b` (чат/edit/apply, ~4.7 GB) и
  `qwen2.5-coder:1.5b-base` (FIM-автокомплит, ~1 GB).

**Что показать:**

```powershell
ollama list
ollama ps
```

и вывод `ollama list`, где видно обе модели.

## 0:45–2:15 — Конфигурация локального ассистента

**На экране:** файл `~/.continue/config.yaml` и
`~/.continue/rules/alex-glad-challenge.md`.

**Что говорить:**

1. Правила проекта перенесены из Дня 1 в системный промпт локальной модели.
   Полный `AGENTS.md` не влезает в контекст 7b-модели без вреда, поэтому
   используется выжимка `rules-agents-short.md`.
2. Контекст настроен сознательно узко: текущий файл, правила проекта
   (`AGENTS.md`, `.omp/RULES.md`) и релевантные куски codebase.
   `docs/`, `terminal` и `localhost`-провайдеры не подключены — для 7b это
   шум.
3. Главная **gotcha**, которую нужно проговорить: `num_ctx` задан явно
   (`16384` для чата, `4096` для автокомплита). Ollama молча режет хвост
   промпта, если размер не указан — на этом проекте уже наступали на эту
   болью.
4. Для кода используется низкая температура: `0.1` для чата, `0.05` для
   автокомплита — меньше галлюцинаций в API.

**Что показать:**

```powershell
cp docs/advanced-day-04/continue-config.yaml ~/.continue/config.yaml
mkdir -p ~/.continue/rules
cp docs/advanced-day-04/rules-agents-short.md ~/.continue/rules/alex-glad-challenge.md
```

И содержимое `config.yaml` с акцентом на блоки `models`, `rules`, `context`.

## 2:15–3:00 — Демонстрация автокомплита

**На экране:** любой TS-файл проекта, например `challenge/src/core/types.ts`.

**Что говорить:**

- Автокомплит работает на малой base-модели `qwen2.5-coder:1.5b-base`.
- Она заточена под FIM (fill-in-the-middle) токены, поэтому быстрее и
  лучше подходит для однострочных дополнений, чем 7b-инструкт.

**Что показать:**

- Начать писать новую функцию или поле в интерфейсе.
- Показать, как Continue.dev предлагает серое продолжение.
- Нажать `Tab` и принять несколько дополнений.
- Показать в статусе скорость автокомплита (~76.8 tok/s на этом железе).

## 3:00–5:30 — Три боевые задачи

**Метод:** те же промпты, что давались облачному ассистенту в Днях 1–2.
Правила из `rules-agents-short.md` уже в системном промпте. Каждый ответ
сохраняем в отдельный файл для честного сравнения.

### Задача 1 — генерация фичи (3:00–4:30)

**Промпт (копировать в чат Continue):**

```text
Добавь в проект оценку токенов: core-сервис TokenEstimator и веб-endpoint
POST /api/tokens/estimate. Сервис принимает массив сообщений {role, content}
и опциональный budget, считает токены по UTF-8 байтам (4 байта на токен,
округление вверх). Endpoint валидирует тело, вызывает сервис и возвращает
{ok:true,total,remaining,fits}. Покрой сервис и endpoint тестами.
```

**Что показать:**

- Вставку промпта в чат Continue.dev.
- Таймер wall-time (в итоге ~168 с).
- Процесс генерации ответа: видно, как токены появляются построчно.
- Сохранение ответа в `docs/advanced-day-04/local-feature_day1.md`.

**Что сказать после получения ответа:**

- Время сопоставимо с облаком (~2 мин 42 с).
- Но код не проходит по правилам проекта: выдуманная доменная модель
  `{id, text}` вместо `ChatMessage {role, content}`;
- нет `.js`-импортов, `import type`, `readonly`;
- endpoint написан прямо в chokepoint `web/lib/server/challenge.ts`;
- нет `server-only`, zod-схемы в `lib/shared/forms.ts`, `safeMessage`,
  `Cache-Control`;
- тесты в jest-стиле, раннеры перепутаны.
- Итог: ~8 правил из системного промпта нарушено. «Знать правило» ≠
  «применить к коду».

### Задача 2 — агентный Research (4:30–5:00)

```text
Как у нас устроена авторизация в web? Ответь по формату: краткий ответ,
файлы с ролями и path:line, связи между файлами, выводы, открытые вопросы.
```

**Что показать:**

- Открытые вопросы — мета-вопросы («какие функции используются?») вместо

### Задача 3 — точечный Bug Fix (5:00–5:30)

**Файл для демонстрации:** любой SQL-запрос с интерполяцией, например:

```ts
const sql = `SELECT * FROM posts WHERE blog_id = '${blogId}' ORDER BY created_at DESC`;
```

**Промпт:**

```text
В этом файле SQL-запрос собирается через интерполяцию. Исправь уязвимость,
сохранив поведение. Объясни причину одним предложением.
```

**Что показать:**

- Найти файл через поиск по `'\${.*}'` в SQL.
- Вставить промпт в чат.
- Засечь время (~10.5 с).
- Показать дифф: замена на `?` и параметризованный запрос.

**Что сказать:**

- Точечный фикс по явному правилу локальная модель делает с первого раза.
- Это её сильная сторона: маленький, конкретный, хорошо описанный патч.

## 6:45–7:45 — Рекомендация: для чего хватает локальной

**На экране:** тот же слайд/таблица, но с акцентом на выводы.

**Что говорить:**

✅ **Локальная модель достаточна для:**

- точечных фиксов по явному правилу;
- автокомплита однострочников и бойлерплейта;
- переименований и простых рефакторингов;
- вопросов по одному вставленному файлу;
- работы офлайн и с приватным кодом.

❌ **Облако незаменимо для:**

- генерации фич под конвенции проекта;
- агентных профилей (Research, Поиск бага, Граф проекта — весь День 2);
- многофайловых правок;
- ревью диффов и архитектурных решений.

## 7:45–8:30 — Усиление и ограничения

**Что говорить:**

- На 16 GB RAM выбор моделей ограничен.
- Перебраны варианты: `qwen2.5-coder:7b` + `qwen2.5-coder:1.5b-base` —
  лучшая связка без загрузки >5 GB.
- Альтернативы: `qwen3:4b` хуже в FIM, `qwen2.5:7b-instruct` слабее в коде,
  чем coder-версия.
- Полный перебор 2–3 моделей на тех же задачах честно зафиксирован как
  ограничение: железо не позволяет загружать много больших моделей.
