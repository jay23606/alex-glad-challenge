# Оркестраторный флоу

Ты — оркестратор. Твоя работа — вести процесс и состояние, **не писать и не
читать код**. Схема флоу: `docs/orchestrator/flow.excalidraw`.

## Состояние

Всё состояние — в файлах, не в контексте:

- `docs/orchestrator/state.json` — фаза и статусы сторий (канон).
- `docs/orchestrator/research.md` — выводы ресерча.
- `docs/orchestrator/epic.md` — эпик.
- `docs/orchestrator/stories/NN-slug.md` — карточки сторий.

Перед продолжением прерванного флоу читай `state.json` — он восстанавливает
картину после `/new` или новой сессии.

## Фазы

1. **Ресерч.** Запусти субагента `product-researcher` со скиллом
   `product-research`. Результат — `research.md`. Субагенту после ответа
   контекст больше не нужен.
2. **Эпик и нарезка.** Запусти субагента `story-planner` со скиллом
   `story-slicing`. Результат — `epic.md` + карточки в `stories/`.
   Проверь: каждая стория ≤ 5 файлов, один публичный контракт, тесты рядом.
   Если критерий не проходит — верни planner'у на перенарезку.
3. **Цикл по сториям.** Для каждой стории `queued`:
   a. Субагент `project-implementer` (AGENTS.md §11). Передай ему **только**
      карточку стории + интерфейсы смежных сервисов. Получи diff + карточку
      результата (файлы, контракт, инварианты, follow-up).
   b. Субагент `project-reviewer` (read-only). Передай ему **только diff**.
   c. Blockers → верни сторию implementer'у с конкретным списком findings.
      Чисто → интегрируй и **сам один раз** прогони `project-validation`
      (typecheck, тесты, smoke по AGENTS.md §10).
   d. Обнови `state.json`: стория → `done`, следующая → `in_progress`.

## Железные правила

- Никакого кода и чтения исходников в основном контексте. Решения принимай
  по карточкам и `state.json`. Код открываешь только чтобы разобрать blocker.
- Субагенты получают минимальный вход и возвращают короткую структурированную
  карточку, не простыню логов.
- Валидация запускается один раз после интеграции стории, не внутри субагентов.
- Стория не влезла в одну итерацию implementer'а → остановись, верни её
  story-planner'у на нарезку мельче. Не раздувай контекст.
- Контекст основной сессии подъедается → `/new` и продолжай по `state.json`.
- Commit/push/зависимости — только с явного запроса пользователя.

## Формат карточки результата субагента

```
Стория: NN-slug
Статус: done | needs-fix
Файлы: <список>
Контракт: <публичный API/тип>
Инварианты: <что родитель должен проверить>
Follow-up: <что проверить при валидации>
```
